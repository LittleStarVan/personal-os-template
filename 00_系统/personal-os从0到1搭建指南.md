# personal-os 从 0 到 1 搭建指南（小白版）

> 这份文档有两个读者：
> **人**——想给自己搭一套"AI 帮管的笔记库"的你，零基础也能跟着做。
> **AI**——你用的任何一个 AI 助手（不同品牌、不同平台都行）。AI 读这份文档时，请先看文末【附录：给 AI 读者的约定】，再按阶段帮用户执行。
>
> 相关文档：库入口与日常使用见根目录 README.md；设计规格与修订历史见 [[personal-os目录结构v2.2-定稿]]（同目录）。

## 第一部分：先看懂这几个词（名词速查）

这套系统里会出现一些"带概念"的词。不用背，用到时回来看一眼就行。

### 关于笔记本身

| 名词 | 大白话解释 |
| --- | --- |
| **知识库** | 就是一套有固定结构的文件夹 + 笔记。本文里叫 personal-os。 |
| **Markdown（.md 文件）** | 一种纯文本格式，用 `#` 表示标题、`-` 表示列表。记事本就能打开，任何软件都能读，所以它是"谁都看得懂"的通用格式。 |
| **Obsidian** | 一个免费的笔记软件，专门读 Markdown 文件。它只是"打开知识库的窗口"，知识库本身是一套普通文件夹，换软件也丢不了。 |
| **YAML 属性头** | 每篇笔记最上面那几行"标签信息"（记录这篇笔记属于哪个领域、什么类型、什么状态、哪天的）。作用类似快递单：不读内容也能知道里面大概是什么。**所有笔记必须带，不许裸奔。** |
| **双链 `[[笔记名]]`** | 笔记之间的超链接。在 A 笔记里写 `[[B笔记]]`，点一下就能跳到 B。作用是让相关知识自动连成网，而不是散落在各处。 |
| **事实源** | "唯一权威版本"的意思。全系统只认这一份数据，AI 改了这里，别处看到的都是同步过来的。避免"这个表有三个版本，哪个是真的？" |

### 关于"东西往哪放"

| 名词 | 大白话解释 |
| --- | --- |
| **收件箱** | 一个专门的笔记文件（`收件箱.md`），相当于家门口的快递筐：想到什么先扔进来，**不分类、不思考**，有空再统一拆。 |
| **待办池** | 一个专门的笔记文件（`待办事项.md`），相当于四条跑道（工作 / 生活 / 个人发展 / 财务），每条跑道最多同时跑 2 件事。**跑道满了还想加新事，必须先取舍。** |
| **等待区** | 待办池里的一个分区，专门放"卡在别人那里"的事（比如等客户回复）。它和普通待办**分开存放**——卡住的事不占你的注意力名额。 |
| **日记 / 周记** | 按时间排列的记录文件。日记记今天，周记记这一周。它们是"时间轴"：不管事情属于哪个领域，发生了就先记在这一天 / 这一周里。 |
| **复盘** | 事后回头看：这周计划的事完成了吗？没完成的为什么？下次怎么改。 |
| **认知库** | 存"想法原料"的地方：突然的洞察、行业观察、信息差思考。先存着，不急着做。 |
| **创作输出** | 存"决定要做的事"的地方：想法在认知库里孵化成熟、你决定动手了，才搬到这里立项执行。**先存想法，再决定做不做**——和收件箱"不当场分类"是同一个哲学。 |

### 关于 AI 怎么参与

| 名词 | 大白话解释 |
| --- | --- |
| **身份卡** | 给 AI 看的"岗位说明书"。每张卡写清楚：这个角色是干什么的（角色定位）、怎么喊它上班（启动口令）、办事的标准是什么（判断标准）、什么不许干（禁区）。**规则全写在卡里，AI 每次先读卡再干活。** |
| **口令** | 喊 AI 上班的那句话，比如"我要规划今天"。口令本身不含规则，只负责触发——改规则改卡，口令永远不变。 |
| **skill 笔记** | 沉淀下来的"操作手册"：某件事你反复做、总结出套路了，就写成一篇 skill 笔记（怎么触发、判断标准、常见坑、最近验证日期）。下次自己或 AI 遇到同类事，直接照手册办。它有一个特殊字段"最近验证"——**过期的手册比没有更害人**，所以要记录最后一次验证的时间。 |
| **元能力** | "基本功"：表达、逻辑思维、时间管理这类支撑其他一切能力的可迁移能力。 |
| **元能力网络** | 一张汇总表：每篇 skill 笔记都标注它依赖哪些基本功，表里统计哪项基本功被依赖得最多（被依赖多 = 最重要），复盘时照表补短板。 |
| **记录 ≠ 执行** | 你随口说"记一下明天要交报告"，AI 只负责记下来，**不许自作主张去帮你写报告**。只有你说"帮我做"才算下令。这是防 AI 越权的第一条纪律。 |

### 关于技术组件（可选，先有个印象）

| 名词 | 大白话解释 |
| --- | --- |
| **MCP** | AI 和笔记库之间的"数据线/插座"。插上它，AI 才能直接读写你的笔记文件。 |
| **FNS（笔记同步服务）** | 装在自己租的云服务器上的同步软件，让电脑和手机上的笔记保持实时一致。 |
| **内网穿透（cpolar 等）** | 家里的电脑/服务器没有公网地址，手机在外面连不上。内网穿透相当于给服务器开一个临时的公网门牌号，让手机找得到它。 |
| **冷备份** | 每周日把整个知识库打包存一份到 GitHub（私有仓库），防误删、防灾难。它和"日常同步"是两回事：同步管"多设备一致"，备份管"丢了能找回"。 |

## 第二部分：这套系统到底在干什么

一句话：**笔记库是唯一账本，AI 是记账员，规则写在纸上（文件里），AI 每次上岗先读规则。**

它由三层组成：

1. **数据层（骨架）**：固定的文件夹结构 + 每篇笔记的属性标签。建好基本不动。
2. **流转层（日常）**：事情的生命周期——先扔收件箱 → 变成待办 → 记进日记 → 周末复盘进周记 → 沉淀成知识。每天都在转。
3. **智力层（越用越聪明）**：身份卡、skill 手册、元能力网络。每周长一点，系统越用越懂你。

三条设计哲学（理解了这个，剩下的都是细节）：

1. **零决策记录**：随手记的时候不许纠结"该放哪"，全部进收件箱。分类是周末归档时（有 AI 帮忙、有完整上下文）的事。
2. **规则写成文件**：AI 的记性是一次性的，文件的记性是永久的。所有规矩都写成笔记文件，AI 每次先读文件再动手。换 AI 平台？只换"插头"，规则一个字不用改。
3. **记录不等于执行**：AI 只在你明确下令时才动手，平时只负责记。

## 第三部分：四步搭起来

总路线：

```javascript
第一步（半天）：搭骨架 —— 建文件夹 + 写三个规则文件 + 开收件箱和待办池
第二步（第 1 周）：跑日常 —— 每天记、睡前归档、周日复盘
第三步（第 1~2 周）：接 AI —— 先电脑端，再手机端（可选）
第四步（长期）：长脑子 —— 攒身份卡、攒手册、攒基本功
```

**第一步做完当天就能用。后面每步都是加分项，不是门槛。**

### 第一步：搭骨架（半天）

**1. 建文件夹**

```javascript
personal-os/
├── 00_系统/              ← 装规则的地方（系统的"操作系统"）
│   ├── 身份卡/            ← 给 AI 的岗位说明书，先空着，第二步填
│   ├── 模板/              ← 日记等固定格式，先放一个日记模板
│   ├── 命名规范与使用说明.md
│   └── 运维/              ← 服务器配置，第三步再填
├── 日记/                  ← 时间轴：按月度分子文件夹
├── 周记/                  ← 复盘时间轴：按年度分子文件夹
├── 10_个人发展/           ← 学习、成长、兴趣、读书
├── 20_工作/               ← 职业象限（二级目录按需自建）
├── 30_生活/               ← 家庭、人际、居住
├── 40_财务/               ← 账本、资产、重大决策
├── 收件箱.md
├── 待办事项.md
└── assets/                ← 小图片附件（大于 2MB 的照片放网盘，库里只留链接）
```

记住三条"不焦虑铁律"，写进命名规范里：

1. 一级文件夹只加不改——建错了也不许大改，新需求先靠属性标签解决；
2. 新东西先进收件箱——不许当场纠结放哪；
3. 改习惯改规则文件——不许动文件夹结构。

**2. 写三个规则文件**（时间花在这最值）

- **`00_系统/命名规范与使用说明.md`**：文件夹怎么命名、笔记属性头必填哪几项、改内容时属性要不要跟着改、各类东西归哪个目录（速查表形式）。
- **`00_系统/AI协作默认规范.md`**：给 AI 的四条铁律——
  - H1 输出前先确认，有疑问就问，不许瞎猜；
  - H2 改任何文件前，先把改动内容念给你听，你点头才写；
  - H3 删除任何东西前，先列清单等你确认，默认不删；
  - H4 你说"记一下/聊聊"时只记录；你说"帮我做"才执行。
- **`待办事项.md`**：按"四轨制"建三个分区（进行中 / 等待区 / 待处理区），池纪律写在文件开头（每域≤2、等待区物理分离、待处理区每周过一遍）。

**3. 开 git 备份（可选）**

```bash
cd personal-os
git init && git add -A && git commit -m "初始化"
# 关联一个 GitHub 私有仓库
```

**纪律：每周日提交一次，平时不提交。** 平时多设备同步靠同步服务，不靠 git。
git 是「冷备份」层——防误删、防灾难；不配它系统也能跑，同步服务管多设备一致，这层以后随时能补。

**4. 装三个 Obsidian 插件（5 分钟）**

在社区插件市场搜索安装：

| 插件 | 用途 | 是否必须 |
| --- | --- | --- |
| Notebook Navigator | 日历侧栏：点任意一天直接定位/创建当天日记 | 强烈建议 |
| PDF++ | 在库内直接阅读、批注 PDF | 强烈建议 |
| Fast Note Sync | 多设备实时同步 | 可选——需要自己租服务器或阿里云；只在电脑上使用则不需要 |

**5. 验收**：文件夹建好；三个规则文件写完；当天往收件箱扔至少 3 条东西（配了 git 的顺手做首次提交）。

### 第二步：跑日常（第 1 周）

每天只做三件事：

1. **随手记**：想到什么，一句话扔进收件箱（带日期，只追加不改）。
2. **睡前 10 分钟**（可以让 AI 代劳）：归档收件箱（每条四选一：转待办 / 并进已有笔记 / 孵化成想法 / 删掉）→ 把昨天没做完的捞到今天 → 排好明天的计划，写进明早的日记。
3. **周日 30 分钟**：收件箱清零 + 待办池全检 + 生成周记 + git 提交。

配套的四个"口令"（喊 AI 上班的话）：

| 你说 | AI 干什么 |
| --- | --- |
| 我要规划今天 | 捞昨天没做完的 + 处理收件箱 + 建好今天的日记（含"今日三件要事"，最多 3 件） |
| 我完成了×× | 在日记里勾掉，同步待办池；有空位时问你要不要补位 |
| 今日复盘 | 统计完成率，逐条问没做完的怎么办（明天继续 / 转长期 / 放弃） |
| 生成本周总结 | 读本周所有日记，生成周记，提醒你备份 |

**这四个口令怎么落到你的 AI 上？** 把"口令 → 去读哪张身份卡 → 按卡执行"写成一段指令，粘贴到你 AI 助手的自动化 / 快捷指令里。规则改了就改身份卡，口令文本永远不动。

第一周没有历史日记是正常的——AI 第一次规划时发现库里是空的，会直接问你"今天有哪些事？"，你说它记，然后再建日记。**顺序不能乱：先问 → 再记 → 再建日记 → 最后播报。**

### 第三步：接 AI（第 1~2 周）

**电脑端（先做，性价比高）**：不用装任何东西，记住一句开场白——

> "先读 `00_系统/AI协作默认规范.md` 和 `00_系统/命名规范与使用说明.md`，之后所有操作遵守这两个文件。"

任何 AI 平台都认这个办法，因为规则在文件里，不在 AI 脑子里。

**手机语音端（可选，体验最好但部署最重）**：基础版只用电脑的话可以跳过本节。想要"睡前躺着说句话就能复盘"的体验，才需要这套链路：

```javascript
手机语音助手 → MCP 数据线 → 内网穿透（临时公网门牌号）→ 云服务器上的同步服务 → 笔记库
```

手机是"输入主战场"（速记、语音），但规则要明白：**语音 AI 只负责新建文件，不改旧文件**（防误改），旧内容你在 Obsidian 里手动整理。

### 第四步：长脑子（长期）

日常转顺了之后，系统会自己变聪明：

1. **加身份卡**：新场景（管钱、管健身、管情绪）就新建一张岗位说明书，不动文件夹。
2. **攒 skill 手册**：反复做的事总结出套路就入库，标注"最近验证"日期。
3. **记元能力**：手册上标注靠哪些基本功，汇总看哪项最常用，照着补短板。
4. **养想法**：灵感进认知库，决定做了才立项进创作输出。

## 第四部分：避坑清单（全是真实踩过的）

1. 随手记的时候纠结分类 → 决策疲劳。**收件箱就是为此存在的。**
2. 给语音 AI 的指令没写"只记录不执行" → 它一定自作主张。
3. 把规则写进口令文本里 → 改规则要改 N 处。**规则只在身份卡里。**
4. 项目立项完就不管 → 项目躺尸。**立项必须在待办池里放一个下一步动作。**
5. AI 任务匹配不上就猜一个 → 语音误识别会错勾任务。**必须列出让用户重说。**
6. 每改一篇笔记就 git 提交 → 备份变成噪音。**每周日一次。**
7. 以为手册换平台还能用 → 换平台就用一句"先读规范文件"。
8. 想一次做完美 → **规则厚度 = 纠偏次数。** 跑歪了，改一处，再跑。

## 附录：给 AI 读者的约定

如果你是 AI 助手，用户把这份文档给了你，请遵守：

1. **先通读全文**，再动手。不要跳段执行。
2. 帮用户搭建或操作时，**写任何文件前先把内容复述给用户确认**；删除前列清单确认；默认不删。
3. 用户说"记录、帮我记、聊聊"时**只记录**，不联网搜索、不代执行、不自建方案文档；用户明确说"帮我做"才进入执行。
4. 操作文件时严格遵循用户库内的 `00_系统/命名规范与使用说明.md` 和 `00_系统/AI协作默认规范.md`（若用户已建好库，这两个文件优先级高于本文档）。
5. 日期、星期、文件名必须按真实当前时间生成，禁止编造。
6. 不确定的事问用户，**禁止猜**。
