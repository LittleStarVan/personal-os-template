## 一、二级目录的判断标准（本版核心约定）

**一个二级目录值不值得预置，只问一句话：它的路径有没有被工作流写死（口令 / 身份卡 / 模板里直接引用）？**

- **写死了** → 必须预置，否则 AI 按口令执行时会找不到地方（如：账本/、日记/）
- **没写死** → 不预置。个人内容用两个 lighter 的工具组织：
  1. **YAML 属性**（领域/类型/状态/日期）——负责「查找归类」
  2. **双链 `[[ ]]`**——负责「知识成网」

> 换句话说：**文件夹管结构，属性管分类，双链管关联。** 能用属性和双链解决的，绝不再开文件夹。这个约定让同一套骨架可以承载完全不同的个人内容——你放客户档案，他放民宿经营，目录树一个字都不用改。

## 三、空壳域怎么用（20_工作 / 30_生活 示范）

以工作域为例，三种常见需求都不需要新建「二级目录」：

| 需求 | 做法 | 例子 |
| --- | --- | --- |
| 放一类资料（如客户档案） | 直接放笔记，YAML `类型: 客户卡` 标记 | 文件名 = 企业全称，属性里写简称/状态/最近触达日 |
| 一次战役（如季度摸排） | 一篇跟进表笔记 + YAML `项目: 2027复审摸排` | AI 维护表格，你只口述/发截图 |
| 一个进行中的项目 | 才建文件夹：20_工作/项目/项目名/ | 结项后整个文件夹转归档 |

**什么时候才允许新建二级目录？** 当某个类目下笔记超过 ~20 篇、且属性筛选已经不便时——那是「数据结构长大了」的信号，不是搭建第一天该做的事。

## 四、三条铁律（全版本通用）

1. **一级目录只增不改**——建错了也不许大改，新需求先靠 YAML 属性解决
2. **新内容先进收件箱**——不许当场纠结放哪，分类是周末归档时的事
3. **改习惯改规则文件，不动文件夹**——规则在 00_系统/，目录是骨头，不是习惯
